# Paperclip reference for our deployment

As of 2026-10-28. Covers v2026.1023.0 (what we run) and canary/v2026.1028.0-canary.6 (latest tag; the latest stable tag is still v2026.1023.0, so there is no newer stable release to upgrade to).

How this was built: source read from `paperclipai/paperclip` at tag `v2026.1023.0` (commit `1b4c803816e82b0265c8422e1a804327a7ed8c54`), plus the release notes from master `40c1ab36cdac70c85dc8fe5e912431834fdb691b`. The Docker image itself was not pulled or run, so anything about "what is in the image" is read from the Dockerfile at the tag. The official docs site is <https://docs.paperclip.ing> (its source is `docs/` in the repo; where docs and code disagree I say so and trust the code).

## Top findings (read these first)

1. **Budgets will probably auto-pause every agent, and the whole company, after the first Hermes run.** Hermes v0.22.5 reports tokens but no cost; Paperclip then records the cost event as "unpriced"; a budget policy defaults to `unpricedUsagePolicy: block`, which treats the scope as over its limit. Details and fix in section 7.1.
2. **The built-in hourly DB backups are already running in our setup** (external Postgres included), contrary to the DECISIONS.md line "No backups". They are written to the `paperclip-data` volume as gzip SQL, by Paperclip's own JavaScript dumper, because the Dockerfile installs no `pg_dump`. Section 4 has the restore commands.
3. **Hermes gets no Paperclip credential.** `hermes_gateway` does not receive a run JWT, only the prompt text. Unless Hermes is given an agent key, it cannot comment on or close issues through the API. Section 6.

## 1. Core concepts

- **Company.** Top-level unit; one instance can host several. Has a name, status (`active`/`paused`/`archived`), and a monthly budget in cents. ([core-concepts.md](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/docs/start/core-concepts.md), [companies.md](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/docs/api/companies.md))
- **Agent.** Has `adapterType` + `adapterConfig`, `role`, `title`, `reportsTo`, `capabilities`, `budgetMonthlyCents`, status (`idle`, `running`, `error`, `paused`, `pending_approval`, `terminated`). Roles are a fixed enum: `ceo cto cmo cfo security engineer designer pm qa devops researcher general` ([constants.ts#L46](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/shared/src/constants.ts#L46)). Create body: [validators/agent.ts#L86](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/shared/src/validators/agent.ts#L86).
- **Org chart.** `reportsTo` forms a strict tree used for escalation; `GET /api/companies/{id}/org` returns it ([agents.ts#L3827](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/routes/agents.ts#L3827), [core-concepts.md](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/docs/start/core-concepts.md)). Our roster sets no `reportsTo`, so the chart is flat. The "Reports to: The Major / The Chief" column in `agents/README.md` is documentation only, because Claude and Petter are not Paperclip agents.
- **Issues** are the unit of work: statuses `backlog todo in_progress in_review done blocked cancelled` ([constants.ts#L189](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/shared/src/constants.ts#L189)). One assignee (`assigneeAgentId`). Moving to `in_progress` needs an atomic checkout (409 if another agent holds it) ([heartbeat-protocol.md](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/docs/guides/agent-developer/heartbeat-protocol.md)).
- **How an agent wakes.** Agents do not run continuously; each wake is a "heartbeat run". Sources: `timer`, `assignment`, `on_demand`, `automation`; a second wake while one is running is coalesced ([agents-runtime.md](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/docs/agents-runtime.md)).
  - *Assignment:* creating an issue with an assignee and any status other than `backlog` wakes the assignee ([issue-assignment-wakeup.ts#L43](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/services/issue-assignment-wakeup.ts#L43), [issues.ts#L12631](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/routes/issues.ts#L12631)). Omitting `status` gives `todo` if assigned, else `backlog` ([issue.ts#L669](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/shared/src/validators/issue.ts#L669)). Assignment/on-demand wakes are on unless `runtimeConfig.heartbeat.wakeOnDemand` (or the other `wakeOn*` keys) is false ([heartbeat-policy.ts#L10](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/services/heartbeat-policy.ts#L10)).
  - *Timer heartbeat is off by default:* `enabled` defaults to false and `intervalSec` to 0 ([queue.ts#L396](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/services/heartbeat/queue.ts#L396)); the UI default is also off, 300 s once toggled ([agent-config-defaults.ts#L29](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/ui/src/components/agent-config-defaults.ts#L29)).
  - *Other wakes:* a comment on the issue, `POST /api/agents/{id}/wakeup`, `POST /api/agents/{id}/heartbeat/invoke`, approval resolution, routines.
- **Runs.** A heartbeat run has status `queued running succeeded failed timed_out cancelled`, logs, and usage/cost ([agents-runtime.md](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/docs/agents-runtime.md)); list with `GET /api/companies/{id}/heartbeat-runs` ([agents.ts#L6608](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/routes/agents.ts#L6608)). `plan_only`/`empty_response` runs trigger bounded continuation wakes ([heartbeat-protocol.md](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/docs/guides/agent-developer/heartbeat-protocol.md)).
- **Routines and triggers.** A routine is a recurring task assigned to an agent; each fire creates a run/issue for the assignee ([routines.md](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/docs/api/routines.md)). Status `active|paused|archived`; `concurrencyPolicy` default `coalesce_if_active`; `catchUpPolicy` default `skip_missed` ([constants.ts#L633](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/shared/src/constants.ts#L633), [routine.ts#L65](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/shared/src/validators/routine.ts#L65)). Trigger kinds: `schedule` (5-field cron + IANA timezone, default UTC), `webhook`, `api` ([routine.ts#L139](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/shared/src/validators/routine.ts#L139)). `{{...}}` in title/description is a variable ([routine.ts#L24](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/shared/src/validators/routine.ts#L24)).
- **Budgets.** Cents, per company and per agent (projects are lifetime), window `calendar_month_utc` ([agents.ts#L4679](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/routes/agents.ts#L4679), [budgets.ts#L631](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/services/budgets.ts#L631)). `warnPercent` default 80 (soft alert), `hardStopEnabled` default true ([budget_policies.ts#L16](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/db/src/schema/budget_policies.ts#L16)). At 100% the scope is paused with `pauseReason: budget` and a budget incident/approval is raised; it resumes when the budget is raised, an incident is resolved, or the UTC month rolls over; manual pauses are never auto-released ([budgets.ts#L283](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/services/budgets.ts#L283), [#L570-L596](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/services/budgets.ts#L570), [costs-and-budgets.md](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/docs/guides/board-operator/costs-and-budgets.md)). Spend only counts what the adapter reports (section 7.1).
- **Approvals.** Types `hire_agent`, `approve_ceo_strategy`, `budget_override_required`, `request_board_approval` ([constants.ts#L689](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/shared/src/constants.ts#L689)). If `company.requireBoardApprovalForNewAgents` (default false) is on, `POST /agents` returns 409 and hires go through `POST /agent-hires` as `pending_approval` ([agents.ts#L4527](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/routes/agents.ts#L4527), [companies.ts schema](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/db/src/schema/companies.ts#L19)).
- **Who can call the API** (actor sources set in [auth.ts](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/middleware/auth.ts)):

| Principal | What it is | Notes |
|---|---|---|
| Board user | Human with a Better Auth session cookie; `instance_admin` role plus per-company memberships | Browser mutations must carry a trusted `Origin`/`Referer` ([board-mutation-guard.ts](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/middleware/board-mutation-guard.ts#L100)). Instance admin alone does not grant company access ([companies.md](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/docs/api/companies.md)). |
| Board API key | `pcp_board_<48 hex>`; acts as the user who made it; stored as sha256 | Default TTL 30 days (`expiresAt` omitted); `expiresAt: null` never expires ([board-auth.ts#L14](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/services/board-auth.ts#L14), [#L212](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/services/board-auth.ts#L212)). ## 2. Adapters

- **List.** Known types: `process http claude_local codex_local paperclip_runner cursor_cloud gemini_local grok_local hermes_gateway hermes_local kimi_local opencode_local pi_local cursor openclaw_gateway` ([constants.ts#L27](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/shared/src/constants.ts#L27)). All are registered at boot, plus a retired `acpx_local` that only reports failure ([registry.ts#L891-L912](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/adapters/registry.ts#L891)). Nothing needs enabling. `paperclip_runner` is an experimental Rust runner behind an instance setting; extra adapters (for example `droid_local`) install as external plugins through the adapter manager ([overview.md](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/docs/adapters/overview.md)).
- **`hermes_gateway`** calls an already-running Hermes API server: `POST /v1/runs`, SSE `GET /v1/runs/{id}/events`, polling `GET /v1/runs/{id}`, `POST /v1/runs/{id}/stop` on timeout ([index.ts#L34-L56](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/adapters/hermes/src/gateway/index.ts#L34)). Config fields ([config-schema.ts](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/adapters/hermes/src/gateway/server/config-schema.ts)):

| Field | Meaning |
|---|---|
| `apiBaseUrl` (required) | Hermes API URL, e.g. `http://127.0.0.1:8642` |
| `apiKey` (required) | Hermes `API_SERVER_KEY`; sent as `Authorization: Bearer`. Stored as a company secret reference |
| `sessionKeyStrategy` | `issue` (default), `agent`, `run`, `none`; becomes `X-Hermes-Session-Key` |
| `timeoutSec` / `eventReconnectMs` | 600 / 2000 defaults |
| `paperclipApiUrl` | Only echoed to Hermes in the prompt; not a credential |
| `headers`, `dangerouslyAllowInsecureRemoteHttp` | Extra non-secret headers; escape hatch for non-loopback plain HTTP |
| `instructions` | Stable system instructions sent in the run body |

  Plain HTTP is accepted only for loopback hosts ([transport-security.ts#L23](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/adapters/hermes/src/gateway/server/transport-security.ts#L23)), which is why `hermes` shares `paperclip`'s network namespace in compose.
- **`supportsInstructionsBundle: false`** ([gateway/index.ts#L68](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/adapters/hermes/src/gateway/index.ts#L68)): there is no managed AGENTS.md. The brief goes in `adapterConfig.instructions`, which becomes the `instructions` field of the Hermes run; without it a one-line default is sent ([execute.ts#L393-L411](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/adapters/hermes/src/gateway/server/execute.ts#L393)). The `input` field carries only a short identity header (agent/company/run id, optional Paperclip URL) and the wake/task text ([execute.ts#L335-L388](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/adapters/hermes/src/gateway/server/execute.ts#L335)). Edit via `PATCH /api/agents/{id}` with `{"adapterConfig":{"instructions":"..."}}`; adapterConfig is merged, not replaced ([agents.ts#L5232-L5236](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/routes/agents.ts#L5232)).
- **Why the wizard may only show Claude.** The first-run wizard lists adapters from the UI registry but excludes `process`, `http`, `paperclip_runner` ([OnboardingWizard.tsx#L153](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/ui/src/components/OnboardingWizard.tsx#L153)) and anything with `hideFromVisualSelection`, which `hermes_gateway` has ([adapter-display-registry.ts#L104-L109](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/ui/src/adapters/adapter-display-registry.ts#L104)). Only `claude_local` and `codex_local` are marked `recommended` ([#L70-L83](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/ui/src/adapters/adapter-display-registry.ts#L70)). The filter applies to the wizard only; the API and later forms accept `hermes_gateway`.
- **Where local adapters run.** `claude_local`, `codex_local`, `opencode_local`, `gemini_local`, `kimi_local`, `hermes_local`, `process` and friends spawn child processes **inside the Paperclip container**, as user `node` (the entrypoint ends in `exec gosu node`) with `HOME=/paperclip`; the image ships those CLIs ([Dockerfile#L177](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/Dockerfile#L177), [#L208](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/Dockerfile#L208), [docker-entrypoint.sh](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/scripts/docker-entrypoint.sh), [docker.md](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/docs/deploy/docker.md), [agents-runtime.md §9](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/docs/agents-runtime.md): "run unsandboxed on the host machine"). SSH or sandbox execution targets exist but sit behind the experimental Environments setting. **Consequence for secrets:** a child inherits the container environment minus `PAPERCLIP_*` keys ([server-utils.ts#L3513-L3530](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/adapter-utils/src/server-utils.ts#L3513), [#L4720](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/adapter-utils/src/server-utils.ts#L4720)), so `DATABASE_URL` and `BETTER_AUTH_SECRET` from `paperclip.env` are visible to it, and the same user can read `/paperclip/instances/default/secrets/master.key`. Do not put any local-adapter agent, or any provider key, in this container.

## 3. Deployment

- **Modes.** `local_trusted`: loopback only, no login, auto-created local board. `authenticated`: Better Auth login, with exposure `private` (auto base URL, hostname guard, browser first-admin claim) or `public` (explicit public URL, stricter checks) ([deployment-modes.md](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/docs/deploy/deployment-modes.md), [DEPLOYMENT-MODES.md](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/doc/DEPLOYMENT-MODES.md)). Public mode refuses to start without `DATABASE_URL` (no embedded Postgres) or without a public base URL ([index.ts#L349](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/index.ts#L349), [#L684](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/index.ts#L684)). The private-hostname guard is off in public mode, so `http://127.0.0.1:3100` works for the roster script ([app.ts#L297-L305](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/app.ts#L297)).
- **Env-only operation.** Environment beats `config.json` for everything we use ([config.ts#L224-L330](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/config.ts#L224)); the image points `PAPERCLIP_CONFIG` at a file that does not exist on our volume ([Dockerfile#L218](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/Dockerfile#L218)). With `DATABASE_URL` set the server uses external Postgres ([index.ts#L437](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/index.ts#L437)).
- **Env vars that matter** ([environment-variables.md](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/docs/deploy/environment-variables.md); the doc is incomplete, so the rest are from `config.ts`):

| Variable | Ours | Effect |
|---|---|---|
| `PAPERCLIP_DEPLOYMENT_MODE` / `_EXPOSURE` | authenticated / public | Image default is authenticated/private ([Dockerfile#L219-L220](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/Dockerfile#L219)) |
| `PAPERCLIP_PUBLIC_URL` | https://hq.sectionnine.dev | Auth base URL, allowed hostname, trusted browser origin ([config.ts#L196-L250](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/config.ts#L196), [board-mutation-guard.ts#L55](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/middleware/board-mutation-guard.ts#L55)) |
| `BETTER_AUTH_SECRET` | in paperclip.env | Required ([better-auth.ts#L245](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/auth/better-auth.ts#L245)); also the fallback signing key for agent JWTs |
| `DATABASE_URL` | in paperclip.env | Postgres connection. Pool max defaults to 10 ([database.md](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/docs/deploy/database.md)); our Postgres has `max_connections=30` |
| `HOST`, `PORT` | 0.0.0.0, 3100 | Bind |
| `PAPERCLIP_HOME`, `PAPERCLIP_INSTANCE_ID` | /paperclip, default | All state under `$HOME/instances/default/` ([CLI.md#L1127-L1146](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/doc/CLI.md#L1127)) |
| `PAPERCLIP_SECRETS_MASTER_KEY[_FILE]` | unset | Else `master.key` is auto-created at `$PAPERCLIP_HOME/instances/default/secrets/` ([local-encrypted-provider.ts#L22-L76](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/secrets/local-encrypted-provider.ts#L22)) |
| `PAPERCLIP_SECRETS_STRICT_MODE` | unset | Defaults to true in authenticated mode: sensitive env bindings must be secret refs ([config.ts#L175](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/config.ts#L175)) |
| `PAPERCLIP_AUTH_DISABLE_SIGN_UP` | unset (sign-up open) | Set `true` after the first admin exists ([config.ts#L224](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/config.ts#L224)). Not tested whether it blocks invite sign-up, so set it only after claiming |
| `PAPERCLIP_ENABLE_COMPANY_DELETION` | unset | Defaults to false outside `local_trusted` ([config.ts#L255](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/config.ts#L255)) |
| `PAPERCLIP_DB_BACKUP_ENABLED/_INTERVAL_MINUTES/_DIR/_RETENTION_DAYS` | unset | See section 4 |
| `DO_NOT_TRACK`, `PAPERCLIP_ANNOUNCEMENTS_ENABLED` | 1, unset | See below |

- **First admin.** A fresh authenticated instance reports `bootstrapStatus: bootstrap_pending` on `/api/health` until an `instance_admin` exists. Browser "Claim this instance" works only in `authenticated/private`; "for `authenticated/public`, browser first-admin claim is intentionally disabled" ([DEPLOYMENT-MODES.md#L170-L205](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/doc/DEPLOYMENT-MODES.md#L170)). The `/board-claim` URL printed at startup is a different thing: it exists only when the sole admin is the old `local-board` user, i.e. after migrating from `local_trusted` ([board-claim.ts#L44-L62](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/board-claim.ts#L44)). So the path is `pnpm paperclipai auth bootstrap-ceo`, which prints a one-time `/invite/pcp_bootstrap_...` URL (default 72 h, max 30 days; it revokes older unused bootstrap invites; whichever of invite or browser claim wins first blocks the other) ([auth-bootstrap-ceo.ts](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/cli/src/commands/auth-bootstrap-ceo.ts#L56-L123)).
  - **Why the throwaway config:** the command exits with "No config found" if the config file is missing and does nothing unless `server.deploymentMode` is `authenticated` ([#L65-L72](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/cli/src/commands/auth-bootstrap-ceo.ts#L65)). It takes the DB from `DATABASE_URL` and the printed base URL from `PAPERCLIP_PUBLIC_URL` ([#L21](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/cli/src/commands/auth-bootstrap-ceo.ts#L21), [#L27](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/cli/src/commands/auth-bootstrap-ceo.ts#L27)). The RUNBOOK step 6 command (inline JSON written to `/tmp/bootstrap.json`, `--base-url` given) matches this.
- **Telemetry** (anonymous usage, on by default): off if `PAPERCLIP_TELEMETRY_DISABLED=1` or `DO_NOT_TRACK=1` (or `CI=true`, or `telemetry.enabled:false` in a config file) ([telemetry/config.ts#L70-L82](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/shared/src/telemetry/config.ts#L70), [README.md#L555-L561](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/README.md#L555)); our `DO_NOT_TRACK=1` covers it. There is **no** instance-settings switch for it: General settings hold only `censorUsernameInLogs`, `feedbackDataSharingPreference`, `backupRetention`, `executionMode` ([instance.ts#L25-L34](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/shared/src/validators/instance.ts#L25)), so the RUNBOOK "turn telemetry off if there's a switch" step is moot. Endpoint: `telemetry.paperclip.ing` ([client.ts#L14](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/shared/src/telemetry/client.ts#L14)).
- **Update check.** Only the CLI checks npm for a newer `paperclipai` (once a day); disable with `PAPERCLIP_UPDATE_CHECK=0` or `updates.checkEnabled:false` ([update-notice.ts#L9](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/cli/src/update-notice.ts#L9)). I found no update check in the server.

**Restore (built-in backup).** Paperclip has no restore command for a live instance; `runDatabaseRestore` is used only by the worktree tooling, and it just pipes the file to `psql` ([backup-lib.ts#L1091](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/db/src/backup-lib.ts#L1091)). The dump creates enum types without `IF NOT EXISTS` ([#L693](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/db/src/backup-lib.ts#L693)), so it **must go into an empty database** (I confirmed on PostgreSQL 16 that a second restore over a populated DB fails with `type already exists`). `psql` inside the Postgres container needs no password because the official image uses `trust` on the local socket ([docker-library README](https://github.com/docker-library/docs/blob/master/postgres/README.md)). `hermes` shares `paperclip`'s network namespace, so stop and start both. I ran the drop/create/restore sequence against a scratch PostgreSQL 16 with a dump in the same shape, not against the real container.

```bash
cd /opt/agent-manager
B=/paperclip/instances/default/data/backups
docker compose exec paperclip ls -lt "$B" | head          # pick a file
F=paperclip-YYYYMMDD-HHMMSS.sql.gz                         # edit
docker compose cp "paperclip:$B/$F" "/root/$F"             # works on a stopped container too
docker compose stop hermes paperclip
docker compose exec -T postgres psql -U paperclip -d postgres -v ON_ERROR_STOP=1 \
  -c 'DROP DATABASE IF EXISTS paperclip WITH (FORCE)' -c 'CREATE DATABASE paperclip OWNER paperclip'
gunzip -c "/root/$F" | docker compose exec -T postgres psql -U paperclip -d paperclip -v ON_ERROR_STOP=1 -q
docker compose up -d paperclip hermes
curl -s http://127.0.0.1:3100/api/health                   # status ok, bootstrapStatus ready
```

**Minimal alternative (pg_dump 17 from the postgres container)**, for an off-volume copy or if you set `PAPERCLIP_DB_BACKUP_ENABLED=false`. Run from host cron as root:

```bash
install -d -m 700 /var/backups/paperclip && cd /opt/agent-manager
docker compose exec -T postgres pg_dump -U paperclip --clean --if-exists --no-owner --no-privileges paperclip \
  | gzip > "/var/backups/paperclip/paperclip-$(date -u +%Y%m%d-%H%M%S).sql.gz"
docker compose cp paperclip:/paperclip/instances/default/secrets/master.key /var/backups/paperclip/master.key
chmod 600 /var/backups/paperclip/master.key
find /var/backups/paperclip -name 'paperclip-*.sql.gz' -mtime +14 -delete
```

Restore it with the same stop / drop+create steps as above, but load with `gunzip -c FILE | docker compose exec -T postgres psql -U paperclip -d paperclip -v ON_ERROR_STOP=1 --single-transaction -q` (this form also works over an existing database, tested on PostgreSQL 16). If `master.key` was lost, copy the saved one back to `/paperclip/instances/default/secrets/master.key` (owner `node`, mode 0600) before starting `paperclip`.

**`scripts/paperclip-apply.py` against this** (read from `origin/main` at `192b1aa`; the script and `agents/roster.toml` are not in the local `main` checkout, which is at `fddb7cf`). Mismatches and risks:

1. **Unpriced-usage block (high).** `PATCH /companies` and agent create each create a budget policy with the default `unpricedUsagePolicy: block`; the script never sets it. See 7.1.
2. **No Paperclip credential for Hermes (high, behavioural).** The script creates no agent key and `hermes_gateway` gets no run JWT. See section 6.
3. **`projectId` on routines (medium).** `docs/api/routines.md` says `projectId` is required; the schema and service accept null ([routine.ts#L66](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/shared/src/validators/routine.ts#L66), [routines svc#L2237](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/services/routines.ts#L2237)), and the script omits it. Expect it to work; if the first apply returns 422, create a project and send `projectId`.
4. **`reportsTo` and `capabilities` are never set (low).** The org chart stays flat; `agents/README.md` implies a hierarchy.
5. **Idempotency of the instructions compare (low).** The script compares `adapterConfig.instructions` from `GET /agents` with the brief, but GET passes strings through `redactSensitiveText`, so a brief containing `Authorization: Bearer ...`, `password=...` and similar would show as changed on every run and be re-PATCHed ([redaction.ts#L733-L744](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/redaction.ts#L733)). The current briefs only contain the word "secrets", so `--dry-run` should read "unchanged". Watch for it after editing briefs.
6. **`apiKey` secret churn (low).** Each plain-string `apiKey` sent creates a new `company_secrets` row; old ones are orphaned ([secrets.ts#L2020](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/services/secrets.ts#L2020)). The script only sends it on create, adapter switch, or `--set-api-key`, which matches this; and the GET value is `***REDACTED***` (truthy), so it is not re-sent.
7. **Saito's old config (low).** On the `claude_local` -> `hermes_gateway` switch the server re-attaches adapter-agnostic keys and instructions-bundle keys from the old config ([agents.ts#L5241-L5255](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/routes/agents.ts#L5241)). Harmless to Hermes, but look at the stored config once.
8. **Board key scope.** `roster-vm` acts as Petter's full board user. The script reads it from a root-only file, which is right.

## 6. Security-relevant behaviour

- **What agents can reach.** A `standard` agent key is broad within its company: it may read same-company agents, projects, issues; comment on or mutate its own and unassigned issues; assign tasks under policy; configure and wake itself; and `canCreateAgents` is true by default, so it can hire peers. It cannot manage environments, tools admin, users, or approve joins ([agent-permission-defaults.md](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/doc/agent-permission-defaults.md)). Agent-authenticated callers cannot set `process` adapter config or change host commands/env of local adapters (same page). Cross-company access is `403` ([authentication.md](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/docs/api/authentication.md)).
- **Hermes and the Paperclip API.** `hermes_gateway` has `supportsLocalAgentJwt: false` ([gateway/index.ts#L67](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/adapters/hermes/src/gateway/index.ts#L67)), so `authToken` is null ([runtime-execution.ts#L241-L251](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/services/heartbeat/runtime-execution.ts#L241)) and the run body is only `input`, `instructions`, `session_id` ([execute.ts#L393-L413](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/adapters/hermes/src/gateway/server/execute.ts#L393)). The execution contract in the prompt says to use `X-Paperclip-Run-Id` "when a Paperclip API key is available". So Hermes agents can only touch Paperclip if given a key. The adapter's own bridge skill says to mint a **`task_bridge`-scoped** key (limited to a parent issue or project, can create tasks only inside that boundary, no company-wide reads) and warns: "Do not put a normal claimed agent API key in an internet-facing Hermes runtime" ([SKILL.md#L13-L45](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/adapters/hermes/skills/paperclip-task-bridge/SKILL.md#L13)). Whether Paperclip itself posts a run's final text onto the issue for this adapter, I could not establish from the code: the run summary (first 2000 chars) is stored in the run result ([execute.ts#L765-L773](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/adapters/hermes/src/gateway/server/execute.ts#L765)) and exposed as `finalText` in run status, but I found no code that turns it into an issue comment. Test this on the supervised first run: does the issue leave `todo`/`in_progress` without a key?
- **Secret storage.** Default provider `local_encrypted`: values are encrypted with a 32-byte master key from `PAPERCLIP_SECRETS_MASTER_KEY`, `..._KEY_FILE`, or an auto-created file `.../secrets/master.key` (mode 0600, mode forced best-effort) ([secrets.md#L170-L183](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/docs/deploy/secrets.md#L170), [local-encrypted-provider.ts#L49-L76](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/secrets/local-encrypted-provider.ts#L49)). Sending `adapterConfig.apiKey` (a schema field marked `secret`) as a plain string creates a managed secret named `hermes_gateway.apikey.<uuid>` and stores a `secret_ref` in the agent row ([secrets.ts#L107](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/services/secrets.ts#L107), [#L1951-L2030](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/services/secrets.ts#L1951)). Agent and board API keys are stored as hashes. The DATABASE_URL password and `BETTER_AUTH_SECRET` live only in env files and the container environment.
- **Code that runs inside the Paperclip container:** local-CLI adapters and `process` (above); plugin workers, one Node process per installed plugin, "trusted code" with no sandbox ([PLUGIN_SPEC.md#L453](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/doc/plugins/PLUGIN_SPEC.md#L453), [PLUGIN_AUTHORING_GUIDE.md#L11](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/doc/plugins/PLUGIN_AUTHORING_GUIDE.md#L11)); workspace provision/runtime-service commands set on projects, which run on the host ([execution-workspaces-and-runtime-services.md](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/docs/guides/board-operator/execution-workspaces-and-runtime-services.md)). Hermes runs in its own container, but it shares `paperclip`'s network namespace, so anything running in the Paperclip container can reach `127.0.0.1:8642`.
- **Browser sign-up** is open by default and the first-admin invite is a bearer secret; keep Cloudflare Access in front and set `PAPERCLIP_AUTH_DISABLE_SIGN_UP=true` once the admin exists.
- **Board key blast radius.** A board key is the human admin. `major-cloud` lives in Claude's environment secrets, so it can hire, read configs and mint more keys. The 365-day TTL is long; consider shorter keys, or `GET /api/board-api-keys` to audit and `DELETE` to revoke.

## 7. Gotchas we've hit (and new ones)

1. **Hermes + budgets = auto-pause (new, high).** Chain, with sources: Hermes v0.22.5 run events carry `usage` with only `input_tokens/output_tokens/total_tokens` ([hermes-agent api_server.py#L4131](https://github.com/NousResearch/hermes-agent/blob/v0.22.5/gateway/platforms/api_server.py#L4131)); the adapter reads `cost_usd` and otherwise leaves `costUsd` unset ([execute.ts#L699-L725](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/adapters/hermes/src/gateway/server/execute.ts#L699)); accounting marks a non-`process` adapter's event `unpriced` when `costUsd` is null ([run-cost-accounting.ts#L100](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/services/run-cost-accounting.ts#L100)); a policy with `unpricedUsagePolicy != allow` counts any unpriced event as over budget ([budgets.ts#L226](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/services/budgets.ts#L226), [#L575](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/services/budgets.ts#L575)) and pauses the scope; the default is `block` ([budget_policies.ts#L18](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/packages/db/src/schema/budget_policies.ts#L18)). The v2026.1023.0 notes list this as a breaking change: "Budgets hold on unpriced usage by default ... Set the policy to `allow` to keep running" ([release notes](https://github.com/paperclipai/paperclip/blob/40c1ab36cdac70c85dc8fe5e912431834fdb691b/releases/v2026.1023.0.md)). Not run live; expect the first completed run to trip it. The company-level policy (20 USD) uses the same default, so it would pause everyone. **Fix:** after `paperclip-apply.py` creates the agents, send for the company and each agent `POST /api/companies/{cid}/budgets/policies {"scopeType":"agent","scopeId":"<id>","unpricedUsagePolicy":"allow"}` (an existing policy keeps its amount, [budgets.ts#L661](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/services/budgets.ts#L661)); better, add it to the script. Cost: Paperclip then records 0 spend for Hermes agents, so per-agent budgets stop enforcing and the OpenRouter $20 key is the only real cap. Paperclip-side numbers will read 0 and the Hermes sessions API (`actual_cost_usd`) would be the place for real figures.
2. **Env-only container needs a throwaway config for the CLI.** `bootstrap-ceo` aborts without a config file and without `deploymentMode: authenticated` in it (section 3).
3. **Browser claim is disabled in authenticated+public.** Use the bootstrap invite (section 3).
4. **The setup wizard forces a first agent and offers Claude.** It hides `hermes_gateway`. The wizard also seeds a "chief of staff" persona and an onboarding task that does not auto-wake ([agents.ts#L4631](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/routes/agents.ts#L4631), [issues.ts#L12618-L12624](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/routes/issues.ts#L12618)). A paused `claude_local` Saito never runs; if it were resumed it would execute `claude` inside the container with the container's environment (section 2). The script switches the adapter and, by design, leaves him paused.
5. **Board keys default to 30 days**, from both the CLI login challenge and `POST /board-api-keys` without `expiresAt`; we mint 365 with `--ttl-days 365` or `expiresAt` ([board-auth.ts#L14](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/server/src/services/board-auth.ts#L14), [token.ts#L240](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/cli/src/commands/client/token.ts#L240)). `expiresAt: null` / `--never-expires` also exist.
6. **`hermes` must restart whenever `paperclip` is recreated** (shared network namespace; RUNBOOK troubleshooting).
7. **Imported agents land with timer heartbeats off**, and the Import page can start them paused ([importing-and-exporting.md](https://github.com/paperclipai/paperclip/blob/v2026.1023.0/docs/guides/board-operator/importing-and-exporting.md)); relevant if the roster is ever restored via import rather than the script.
8. **Docs lag code.** `docs/api/routines.md` (projectId), `docs/api/overview.md` (lists only some auth types), `environment-variables.md` (missing `PAPERCLIP_PUBLIC_URL`, `PAPERCLIP_DB_BACKUP_*`, `PAPERCLIP_ANNOUNCEMENTS_ENABLED`, `PAPERCLIP_AUTH_DISABLE_SIGN_UP`). Check `server/src/config.ts` for the truth.
